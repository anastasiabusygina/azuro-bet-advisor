# Задача: Устранение противоречий в руководствах проекта

## Общая информация
- Название задачи: Устранение противоречий в руководствах и правилах проекта
- Краткое описание: Выявление и документирование противоречий между различными правилами проекта
- Основные требования: Каждое противоречие должно быть четко определено и описано в отдельной капсуле
- Критерии успешного выполнения: Все выявленные противоречия структурированы в формате капсул
- Номер родительской задачи: #main

## Анализ кодовой базы
- Список связанных файлов:
  - `.cursor/rules/0-testing-guide-updated.mdc` - руководство по тестированию
  - `.cursor/rules/strict-request-adherence.mdc` - правило строгого следования запросам
  - `.cursor/rules/confirm-and-plan.mdc` - правило подтверждения и планирования
  - `.cursor/rules/task-capsule-planner.mdc` - правило планирования капсульных задач
  - `tests/README.md` - руководство по тестам
  - `docs/technical-guide.md` - техническая документация

- Архитектурные компоненты, которые будут затронуты:
  - Система правил и руководств проекта
  - Процессы разработки и тестирования

- Существующие реализации похожей функциональности:
  - Различные несогласованные правила по тестированию, коммитам и документации

## Капсула 1: Противоречие в правилах мокирования зависимостей

### Описание
Выявлено противоречие между правилами мокирования компонентов в юнит-тестах. В одном документе требуется мокировать всё, в другом - только внешние зависимости.

### Файлы для анализа
- `.cursor/rules/0-testing-guide-updated.mdc` - содержит правило "Мокаем всё в юнит тестах, оставляем настоящие внешние системы в интеграционных"
- `tests/README.md` - описывает правила мокирования только для внешних зависимостей

### Шаги выполнения
1. Подробно описать выявленное противоречие
2. Указать конкретные места в документах, где встречаются противоречивые требования
3. Проанализировать влияние противоречия на процесс разработки
4. Предложить единую формулировку без противоречий

### Критерии завершения
- Противоречие в правилах мокирования четко описано
- Выявлены все затронутые файлы и секции
- Предложена согласованная формулировка правила
