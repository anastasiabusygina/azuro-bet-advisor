# Документация теста configPresenceValidation.test.ts

## Назначение теста

Тест предназначен для проверки наличия обязательной валидации переменных окружения и конфигурации в проекте. Его основная цель - обеспечить, чтобы все конфигурационные данные проверялись с помощью библиотек валидации (Joi, Zod или Yup) перед использованием в приложении.

## Что проверяет тест

Тест выполняет следующие проверки:
- Сканирует все файлы в разрешенных конфигурационных директориях (`src/config/`, `scripts/node/`, `azuro-mapper.ts`)
- Ищет код валидации, используя регулярные выражения для обнаружения паттернов валидации
- Проверяет наличие хотя бы одного файла с валидацией конфигурации

## Поддерживаемые библиотеки валидации

Тест определяет наличие валидации, проверяя следующие паттерны:
1. Joi: `Joi.object(...).validate(...)`
2. Zod: `Zod.object(...).parse(...)` или `Zod.object(...).safeParse(...)`
3. Zod (сокращенный синтаксис): `z.object(...).parse(...)` или `z.object(...).safeParse(...)`
4. Yup: `Yup.object(...).validate(...)` или `Yup.object(...).validateSync(...)`
5. Схемы общего вида: `schema.parse(...)` или `schema.safeParse(...)`

## Пример результата

Если тест не находит валидацию конфигурации в разрешенных файлах, он выбрасывает исключение с сообщением:

```
Не найдена обязательная валидация конфигурации (Joi/Zod/Yup) в разрешённых файлах!
```

Если валидация найдена в одном из файлов, тест проходит успешно, и в лог выводится информация о найденной валидации:

```
Проверяем файл: src/config/env.ts
Содержимое: import { z } from 'zod';

const envSchema = z.object({
  API_KEY: z.string().min(1),
  PORT: z.string().transform(Number).default('3000'),
  NODE_ENV: z.enum(['development', 'test', 'production']),
});

export const env = envSchema.parse(process.env);...
Найдена валидация в файле: src/config/env.ts
```

### Разрешенные директории для конфигурации

Тест проверяет файлы только в следующих директориях:
- `src/config/`
- `scripts/node/`
- `azuro-mapper.ts`

### Рекомендации по исправлению

Если тест не находит валидацию, необходимо:
1. Выбрать библиотеку валидации (Joi, Zod или Yup)
2. Создать схему для валидации переменных окружения или конфигурации
3. Добавить код валидации в один из разрешенных файлов
4. Экспортировать валидированную конфигурацию для использования в приложении

### Пример схемы валидации с Zod

```typescript
// src/config/env.ts
import { z } from 'zod';

const envSchema = z.object({
  API_KEY: z.string().min(1),
  PORT: z.string().transform(Number).default('3000'),
  NODE_ENV: z.enum(['development', 'test', 'production']),
});

export const env = envSchema.parse(process.env);
```
