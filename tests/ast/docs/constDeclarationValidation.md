# Документация теста constDeclarationValidation.test.ts

## Назначение теста

Тест предназначен для обнаружения хардкоженных констант в коде проекта. Его основная цель - обеспечить, чтобы все константы загружались из YAML-файлов или переменных окружения, а не были жестко закодированы в исходном коде.

## Что проверяет тест

Тест выполняет следующие проверки:
- Сканирует все TypeScript файлы в директории `src` с помощью AST (Abstract Syntax Tree)
- Находит все объявления `const` с простыми значениями (строки, числа, boolean, литеральные объекты)
- Проверяет, нет ли хардкоженных значений констант
- Предоставляет возможность игнорировать константы с помощью комментария `@allow-const-hardcode`

## Пример результата

Если тест обнаруживает хардкоженные константы, он выбрасывает исключение с сообщением, содержащим:
- Путь к файлу с хардкоженными константами
- Имена констант, их значения и номера строк
- Рекомендации по исправлению:
  1. Вынести значение в конфигурационный файл
  2. Использовать переменные окружения
  3. Добавить комментарий `@allow-const-hardcode` перед объявлением константы

### Примеры ошибок

```
В файле src/config/api.ts найдены хардкоженные константы:
- API_TIMEOUT: 5000 (строка 15)
- BASE_URL: "https://api.example.com" (строка 18)

Решения:
1. Вынести значение в конфигурационный файл
2. Использовать переменные окружения
3. Добавить комментарий @allow-const-hardcode перед объявлением константы
```

### Разрешение хардкоженных констант

Если в некоторых особых случаях необходимо использовать хардкоженные константы, их можно разрешить, добавив комментарий `@allow-const-hardcode` перед объявлением:

```typescript
// @allow-const-hardcode
const MAX_RETRY_ATTEMPTS = 3;
```
