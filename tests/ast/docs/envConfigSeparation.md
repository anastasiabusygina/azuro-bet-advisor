# Документация теста envConfigSeparation.test.ts

## Назначение теста

Тест предназначен для обеспечения строгого разделения переменных окружения (env) и конфигурации (config) в проекте. Его основная цель - ограничить прямой доступ к переменным окружения только разрешенными файлами и предотвратить смешивание логики получения переменных окружения с бизнес-логикой.

## Что проверяет тест

Тест выполняет следующие проверки:
- Сканирует все TypeScript файлы в директории `src`
- Определяет, является ли файл "разрешенным" для работы с переменными окружения
- Выявляет прямые обращения к `process.env` в неразрешенных файлах
- Проверяет использование `.default()` при определении переменных окружения (запрещено, если настроено)
- Проверяет использование fallback-значений для переменных окружения (запрещено, если настроено)

## Пример результата

Если тест обнаруживает нарушения, он выбрасывает исключение с сообщением, содержащим путь к файлу, номер строки и описание нарушения.

### Примеры сообщений об ошибках

1. Прямое обращение к переменным окружения вне разрешенных файлов:
```
src/services/apiService.ts:15 - Недопустимое обращение к process.env вне разрешённого файла.
```

2. Использование `.default()` при определении переменных окружения:
```
src/config/env.ts:25 - Запрещено использование .default() при определении переменных окружения.
```

3. Использование fallback-значений для переменных окружения:
```
src/config/environment.ts:10 - Запрещено использовать fallback-значения для переменных окружения (process.env.X || 'значение').
```

### Конфигурация

Разрешенные файлы и настройки определяются в конфигурационном файле `envConfigSeparation.config.ts`:

```typescript
export const envConfigSeparation = {
  // Файлы, в которых разрешена работа с переменными окружения
  allowedEnvFiles: [
    'env.ts',
    'environment.ts',
    'config.ts'
  ],
  // Запрет использования .default() при определении переменных окружения
  disallowDefaults: true,
  // Запрет использования fallback-значений для переменных окружения
  disallowFallbacks: true
};
```

### Рекомендации по исправлению

Если тест обнаружил нарушения, рекомендуется:
1. Перенести все прямые обращения к `process.env` в разрешенные файлы конфигурации
2. Экспортировать необходимые значения из этих файлов
3. Использовать экспортированные значения вместо прямого обращения к `process.env`
4. Не использовать fallback-значения напрямую с `process.env`, вместо этого определять их в конфигурационных файлах

### Принцип разделения

Основной принцип: код приложения не должен знать об источнике конфигурации (переменные окружения, файлы конфигурации и т.д.). Вся работа с источниками конфигурации должна быть изолирована в специальных файлах.
