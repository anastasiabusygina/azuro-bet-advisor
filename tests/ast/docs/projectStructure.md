# Документация теста projectStructure.test.ts

## Назначение теста

Тест предназначен для валидации структуры проекта в соответствии с определенной конфигурацией. Его основная цель - обеспечить, чтобы структура проекта соответствовала согласованной архитектуре и не содержала неожиданных директорий.

## Что проверяет тест

Тест выполняет следующие проверки:
- Сканирует директории проекта согласно конфигурации `projectStructure.config.ts`
- Проверяет наличие только разрешенных поддиректорий в каждой зоне проекта
- Выявляет неожиданные директории, которые не соответствуют разрешенной структуре
- Выводит предупреждения о неожиданных директориях, не вызывая падение теста

## Пример результата

Тест не вызывает ошибки, но выводит предупреждения о несоответствиях структуры проекта ожидаемой конфигурации.

### Пример вывода предупреждений

```
⚠️ В "src" найдены неожиданные директории: experimental, deprecated
⚠️ В "scripts" найдены неожиданные директории: outdated
```

### Конфигурация структуры

Разрешенная структура проекта задается в конфигурационном файле `projectStructure.config.ts` в формате:

```typescript
const allowedStructure: ProjectStructure = {
  'src': ['api', 'components', 'config', 'models', 'services', 'utils'],
  'scripts': ['build', 'deploy', 'tools'],
  'tests': ['unit', 'integration', 'e2e', 'fixtures']
};
```

### Расширение конфигурации

Конфигурацию можно расширить с помощью функции `extendStructure`:

```typescript
const projectAllowedStructure = extendStructure({
  'src': [...allowedStructure.src, 'newModule'],
  'customDir': ['subdir1', 'subdir2']
});
```

### Переносимость теста

Тест разработан для возможности повторного использования в других проектах:
1. Скопировать файлы `projectStructure.test.ts` и `projectStructure.config.ts`
2. Настроить `projectStructure.config.ts` в соответствии со структурой проекта
3. Запустить тест с помощью команды: `npm test -- path/to/projectStructure.test.ts`
