# Документация теста testPlacement.test.ts

## Назначение теста

Тест предназначен для проверки правильного размещения тестовых файлов в проекте. Его основная цель - обеспечить согласованную структуру проекта, где все тестовые файлы находятся в соответствующих директориях, что упрощает навигацию по проекту и поддержку тестов.

## Что проверяет тест

Тест выполняет следующие проверки:
- Рекурсивно сканирует все директории проекта в поисках файлов с расширением `.test.ts`
- Исключает из проверки тесты AST (которые находятся в директории `tests/ast`)
- Проверяет, что каждый тестовый файл располагается в директории `tests` или `__tests__`

## Пример результата

Если тест обнаруживает тестовые файлы, размещенные вне правильных директорий, он выбрасывает исключение с сообщением, содержащим путь к файлу.

### Пример сообщения об ошибке

```
❌ src/utils/formatter.test.ts — не в tests/ или __tests__/ рядом с кодом
```

## Правильная структура размещения тестов

В проекте приняты следующие стандарты размещения тестов:

1. **Тесты должны размещаться в директориях `tests` или `__tests__`**
   ```
   src/
     └── utils/
         ├── formatter.ts
         └── tests/
             └── formatter.test.ts
   ```
   
   или
   
   ```
   src/
     └── utils/
         ├── formatter.ts
         └── __tests__/
             └── formatter.test.ts
   ```

2. **AST-тесты размещаются отдельно в директории `tests/ast`**
   ```
   tests/
     └── ast/
         └── testName.test.ts
   ```

## Рекомендации по исправлению

Если тест обнаружил неправильно размещенные тестовые файлы, необходимо:
1. Создать директорию `tests` или `__tests__` рядом с тестируемым функциональным кодом
2. Переместить тестовый файл в эту директорию
3. Обновить импорты в тестовом файле, если требуется

### Пример исправления

Неправильное размещение:
```
src/
  └── utils/
      ├── formatter.ts
      └── formatter.test.ts  // ❌ Неправильно
```

Правильное размещение:
```
src/
  └── utils/
      ├── formatter.ts
      └── tests/
          └── formatter.test.ts  // ✅ Правильно
```

## Почему это важно

Правильное размещение тестов важно для:
1. Поддержания единообразной структуры проекта
2. Упрощения навигации по проекту
3. Четкого разделения функционального кода и тестов
4. Облегчения автоматизации процессов тестирования
5. Улучшения читаемости кодовой базы

## Исключения из правил

Тесты AST (Abstract Syntax Tree) имеют особое размещение в директории `tests/ast`, так как они:
1. Работают на уровне всего проекта, а не отдельных модулей
2. Проверяют структурные аспекты кода, а не функциональность конкретных модулей
3. Имеют специфические зависимости и конфигурацию

Эти тесты не подчиняются общим правилам размещения тестов и исключаются из проверки.
